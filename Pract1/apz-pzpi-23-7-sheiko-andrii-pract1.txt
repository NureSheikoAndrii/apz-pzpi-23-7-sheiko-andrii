ВСТУП
У сучасному світі розробка програмного забезпечення є складним процесом, що вимагає використання перевірених підходів і рішень. Одним із таких підходів є застосування шаблонів (патернів) проєктування, які дозволяють ефективно вирішувати типові задачі, що виникають під час створення програмних систем.
Патерни проєктування були систематизовані групою авторів, відомих як «Gang of Four», у книзі Design Patterns: Elements of Reusable Object-Oriented Software. Вони описують універсальні підходи до організації коду, що сприяють підвищенню його гнучкості, повторного використання та зрозумілості.
Особливе місце серед патернів займають поведінкові патерни, які відповідають за організацію взаємодії між об’єктами. Одним із таких патернів є Iterator (Ітератор), який забезпечує зручний та стандартизований спосіб доступу до елементів колекцій без розкриття їх внутрішньої структури.
Актуальність даної теми полягає в тому, що сучасні програмні системи активно працюють з різноманітними структурами даних, і необхідність ефективного та незалежного доступу до них є надзвичайно важливою.
Метою даної роботи є дослідження патерну проєктування Iterator, аналіз його структури, особливостей застосування, переваг і недоліків, а також розгляд прикладу реалізації.

3 ОПИС ВИКОНАНОЇ РОБОТИ
3.1 Загальна характеристика патернів GoF
Патерни проєктування «design patterns» - це перевірені рішення типових задач, що виникають під час розробки програмного забезпечення. Вони не є готовим кодом, а скоріше шаблонами, які можна адаптувати під конкретну задачу.
Класичний набір патернів був систематизований групою авторів, відомих як «Gang of Four» (GoF). До нього входить 23 патерни, які поділяються на три категорії:
•	Породжувальні «Creational» - відповідають за створення об'єктів, наприклад, Factory Method, Abstract Factory;
•	Структурні «Structural» - визначають спосіб організації класів і об'єктів, наприклад, Adapter, Decorator;
•	Поведінкові «Behavioral» - описують взаємодію між об'єктами та розподіл відповідальностей, наприклад, Observer, Strategy, Iterator.
Патерни дозволяють:
•	підвищити повторне використання коду;
•	спростити розробку складних систем;
•	зробити архітектуру більш зрозумілою;
•	полегшити підтримку та масштабування програм.
Патерн Iterator, належить до поведінкових патернів, оскільки він визначає спосіб взаємодії між колекцією та клієнтським кодом

3.2 Визначення патерну «Ітератор» 
Iterator «Ітератор» - це поведінковий патерн проєктування, який надає стандартний спосіб послідовного доступу до елементів колекції без розкриття її внутрішньої структури. 
Основна ідея патерну полягає у винесенні логіки обходу колекції в окремий об’єкт - ітератор. Це дозволяє клієнтському коду працювати з різними структурами даних через єдиний інтерфейс
Ітератор зазвичай надає такі операції:
•	перехід до наступного елемента;
•	перевірка наявності наступного елемента;
•	доступ до поточного елемента

3.3 Проблема, яку вирішує патерн «Ітератор»
У процесі розробки програм часто виникає необхідність працювати з різними структурами даних, такими як масиви, списки, множини або складні ієрархічні структури - дерева
Без використання патерну виникають такі проблеми: 
•	Жорстка прив'язка до структури даних - клієнтський код знає, як саме організована колекція;
•	Дублювання логіки обходу - для кожної структури потрібно писати окремий цикл;
•	Складність змін - при зміні структури даних потрібно змінювати клієнтський код;
•	Порушення інкапсуляції - внутрішня реалізація колекції стає доступною зовні
Патерн Iterator в той же час, вирішує ці проблеми шляхом:
•	ізоляції алгоритму обходу;
•	приховування внутрішньої структури колекції;
•	надання універсального інтерфейсу для роботи з даними

3.4 Структура патерну «Ітератор»
Патерн складається з кількох основних компонентів:
1. Iterator «Ітератор»
Оголошує інтерфейс для обходу колекції.
Основні методи:
•	hasNext() - перевіряє, чи є наступний елемент;
•	next() - повертає наступний елевмент
2. ConcreteIterator «Конкретний ітератор»
Реалізує інтерфейс Iterator та зберігає поточну позицію в колекції.
3. Aggregate «Агрегат, колекція»
Оголошує метод створення ітератора
4. ConcreteAggregate «Конкретна колекція»
Реалізує метод створення ітератора та повертає відповідний об'єкт
Така структура забезпечує розділення відповідальностей між зберіганням даних і їх обходом

3.5 Ситуації застосування патерну «Ітератор»
Патерн Iterator доцільно використовувати у таких випадках: 
•	коли потрібно забезпечити доступ до елементів складної структури даних без розкриття її реалізації;
•	коли необхідно підтримувати кілька способів обходу, наприклад, прямий, зворотний, фільтрований;
•	коли система повинна працювати з різними типами колекцій через єдиний інтерфейс;
•	коли важливо зменшити залежність між клієнтським кодом і структурою даних;
•	коли потрібно забезпечити можливість одночасного обходу однієї колекції кількома ітераторами.
Прикладом використання є стандартні бібліотеки мов програмування,  де ітератори застосовуються для обходу колекцій, наприклад, Java Collections Framework

3.6 Переваги та недоліки патерну «Ітератор»
Переваги:
•	забезпечує єдиний інтерфейс для обходу різних структур;
•	приховує внутрішню реалізацію колекції;
•	спрощує підтримку та розширення системи;
•	дозволяє реалізовувати різні алгоритми обходу;
•	підтримує принципи ООП, інкапсуляція, SRP
Недоліки:
•	збільшує кількість класів у програмі;
•	може ускладнювати структуру для простих випадків;
•	іноді створює додаткові накладні витрати в пам’яті;
•	не завжди є необхідним при використанні простих циклів

3.7 Приклад реалізації патерну
Приклад реалізації патерну Iterator мовою Java:
// Інтерфейс Iterator
interface Iterator {
    boolean hasNext();
    Object next();
}

// Конкретний Iterator
class NameIterator implements Iterator {
    private String[] names;
    private int index = 0;

    public NameIterator(String[] names) {
        this.names = names;
    }

    public boolean hasNext() {
        return index < names.length;
    }

    public Object next() {
        if (hasNext()) {
            return names[index++];
        }
        return null;
    }
}

// Інтерфейс колекції
interface Container {
    Iterator getIterator();
}

// Конкретна колекція
class NameRepository implements Container {
    private String[] names = {"Іван", "Петро", "Олена"};

    public Iterator getIterator() {
        return new NameIterator(names);
    }
}
У цьому прикладі:
•	NameRepository є колекцією;
•	NameIterator забезпечує доступ до її елементів;
•	клієнтський код може перебирати елементи без знання внутрішньої структури

3.8 Порівняння з іншими патернами
Iterator vs Composite
Iterator vs Composite
Патерн Composite визначає ієрархічну структуру об'єктів (дерево), тоді як Iterator використовується для обходу цієї структури. Iterator доцільно застосовувати тоді, коли потрібно організувати зручний доступ до елементів складної структури, не змінюючи її реалізацію. Ключова різниця полягає в тому, що Composite відповідає за побудову структури, а Iterator - за її обхід.

Iterator vs Visitor
Патерн Visitor дозволяє додавати нові операції до об'єктів без зміни їх класів, тоді як Iterator лише забезпечує доступ до елементів колекції.
Visitor краще використовувати у випадках, коли потрібно виконувати різні операції над елементами структури, не змінюючи їх реалізацію. Основна різниця полягає в тому, що Visitor працює з поведінкою об’єктів, а Iterator - з їх послідовним переглядом.

Iterator vs Strategy
Патерн Strategy дозволяє змінювати алгоритми під час виконання програми, тоді як Iterator визначає спосіб доступу до елементів колекції.
Strategy доцільно застосовувати, коли існує кілька варіантів алгоритмів для однієї задачі. Ключова різниця полягає в тому, що Strategy змінює логіку виконання, а Iterator лише забезпечує зручний доступ до даних

Таким чином, патерн Iterator часто використовується разом з іншими патернами, доповнюючи їх функціональність.

•	підвищує гнучкість та масштабованість програмного забезпечення

Додатково слід зазначити, що даний патерн є базовим і широко використовується у стандартних бібліотеках сучасних мов програмування, що підтверджує його практичну цінність та актуальність
Отже, використання патерну Iterator є доцільним у випадках, коли необхідно забезпечити зручний, гнучкий та незалежний від реалізації доступ до даних у колекціях
